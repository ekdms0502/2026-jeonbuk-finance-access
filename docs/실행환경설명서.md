## 2. 실행 방법

| 단계 | 명령어 또는 설명 |
|---|---|
| 1단계 | 저장소를 받아 폴더로 이동한다.<br>`git clone https://github.com/ekdms0502/2026-jeonbuk-finance-access.git`<br>`cd 2026-jeonbuk-finance-access`<br>(git이 없으면 저장소 페이지의 Code → Download ZIP 압축을 풀어 이동한다) |
| 2단계 | 가상환경을 만들고 활성화한다.<br>`python3 -m venv .venv`<br>`source .venv/bin/activate` (Windows: `.venv\Scripts\activate`) |
| 3단계 | 라이브러리를 설치한다.<br>`python3 -m pip install -r requirements.txt` |
| 4단계 | 전체 검증을 실행한다. 1분 내외 걸리고, 마지막 줄에 `PASS (offline)`이 나오면 정상이다.<br>`bash verify_offline.sh` |
| 5단계 | 대시보드를 연다. 로컬 서버가 필요 없다.<br>`open docs/demo-jeonbuk/index.html` (Windows: `start docs\demo-jeonbuk\index.html`) |

`verify_offline.sh`는 ① `src/*.py` 전체 컴파일 ② 경로 엔진 단위 테스트 ③ 유형·순회·
민감도·대시보드 산출물 재생성과 브라우저 엔진 테스트 ④ 좌표·경계·조인 무결성 재계산
⑤ 가공 데이터 행 수와 JSON 파싱 확인의 5단계를 순서대로 실행한다.

### 개별 단계를 따로 돌리려면

```
PYTHONPATH=src python3 src/build_typology.py                              # 취약유형 군집
PYTHONPATH=src python3 src/build_jeonbuk_route_scenario.py --reuse-matrix # 순회 배정
PYTHONPATH=src python3 src/build_scenario_evidence.py                     # 민감도 감사
PYTHONPATH=src python3 src/build_dashboard_data.py                        # 대시보드 번들
PYTHONPATH=src python3 src/validate_outputs.py                            # 무결성 재계산
```

## 4. 실행 시 유의사항

- **API 키가 없어도 된다.** `verify_offline.sh`와 대시보드는 네트워크 없이 동작한다.
  `.env`의 ECOS 키는 원본을 새로 수집할 때만 필요하고 제출물에 포함되지 않는다.
- **`data/raw/`에는 공개 가능한 원본만 포함했다.** 재배포 제한 스냅샷(은행연합회·신협·새마을금고)과
  카카오 응답 캐시는 이용조건을 고려해 팀이 비공개 보관하며, `south-korea-latest.osm.pbf`(285MB)는
  GitHub 파일당 100MB 제한 때문에 저장소 Release(`raw-data-v1`) 자산으로 제공한다.
  제외분의 SHA-256은 전부 `data/source_manifest.json` 원장에 있어 대조 가능하다.
  제외된 원본이 없어도 `verify_offline.sh`는 전부 통과한다.
- **`verify_source_lineage.sh`(원본 계보 검증)는** Release의 osm.pbf와 비공개 보관 원본을
  `data/raw/`·`data/processed/`에 배치한 뒤 실행하면 75/75 전체 통과한다(원본 전체 보유 환경 전용).
  공개 저장소만으로 실행하면 부족한 파일 목록을 출력하고 중단되며, 이는 정상 동작이다.
  일상 심사에는 `verify_offline.sh`만으로 충분하다.
- **Node.js가 없으면 3단계의 브라우저 엔진 테스트만 건너뛴다.** Python 분석은 그대로 돈다.
- **`osmium` 설치가 실패해도 된다.** 원본 OSM 도로망을 새로 만들 때만 쓴다.
  `numpy`와 `scipy`만 설치해도 `verify_offline.sh`는 통과한다.
- **대시보드는 폴더째 열어야 한다.** `docs/fonts/`가 함께 있어야 글꼴이 정상 표시된다.
- Windows에서 `.sh` 실행이 안 되면 WSL2 또는 Git Bash를 쓴다.
- **`verify.sh`는 API 키 보유 환경용 최소 검증이다.** 심사 시에는 `verify_offline.sh`만 실행하면 된다.
