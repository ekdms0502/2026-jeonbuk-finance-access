# 전북 순회서비스 시나리오 계약

- 계약 버전: v3
- 기준일: 2026-08-12
- 분석 범위: 전북 14개 시군·243개 행정동
- 목적: 화면 설계와 계산 로직을 분리하고 같은 입력에 같은 결과를 제공한다.

## 1. 결론

전북 전체 화면은 `data/processed/jeonbuk_route_scenario.json`에서 만든 축약 번들과
동일한 결정론적 경로 엔진을 읽는다. 운영가정과 입력범위는
`config/jeonbuk_route_default.json`에서 관리하며 생성형 AI API를 호출하지 않는다.

현재 결과는 **시연용**이다. 전북 공식 경로당 목록과 OSM 도로망은 실제 공개
데이터지만 차고지, 장소 사용승인, 시간창, 서비스시간, 차량 재배치는 운영가정이다.
구현 화면은 `docs/demo-jeonbuk/`이며 기존 `docs/demo-jeongeup/` 주소는 이 화면으로 이동한다.

## 2. 입력 계약

| 변수 | JSON 필드 | 기본값 | 변경 영향 |
|---|---|---:|---|
| 차량 대수 | `vehicle_count` | 3대 | 하루 동시 경로 수 |
| 주기 내 운영일 | `operating_days_per_cycle` | 5일 | 전체 경로일 용량 |
| 시군별 최소 배정 | `minimum_route_days_per_active_zone` | 1일 | 14개 시군 공간 형평성 |
| 출발 위치 | `depot.start_outlet_id_by_zone` | 시군별 자동 후보 | 첫 구간·차고지 선택 |
| 복귀 위치 | `depot.end_outlet_id_by_zone` | 출발지와 동일 | 마지막 구간 |
| 운영 시작·종료 | `operating_start/end` | 09:00~17:00 | 일일 시간 제약 |
| 기본 서비스시간 | `service_minutes_default` | 45분 | 거점별 체류시간 |
| 장소 시간창 | `venue_time_window_default` | 09:00~16:30 | 대기·방문 가능 여부 |
| 경로당 장소 수 | `max_stops_per_route` | 4 | 한 경로의 방문 상한 |
| 서비스 주기 | `service_cycle_days` | 7일 | 다음 서비스까지 시간소외 상한 |
| 우선대상 | `target_selector` | 도로거리 3km 초과·기본품질 | 경로 대상 행정동 |
| 우선순위 | `priority_tiers` | 5km 초과 P1, 3~5km P2 | 사전식 목표 순서 |
| 후보 수 | `candidate_count_per_target` | 1 | 대상별 후보거점 풀 |
| 이동시간 가정 | `uniform_speed_kmh` | 40km/h | OSM 거리의 시간 환산 |

대상·우선순위·후보·차고지를 바꾸면 OSM 행렬을 다시 만든다. 차량 수,
운영일, 운영시간, 서비스시간, 장소 수, 주기, 속도만 바꾸면 저장 행렬을 재사용한다.

### 화면 입력 범위

| 입력 | 허용 범위 | 증분 |
|---|---:|---:|
| 차량 수 | 1~10대 | 정수 1대 |
| 주간 운영일 | 1~7일 | 정수 1일 |
| 운영 시작·종료 | 06:00~22:00 | 30분 |
| 장소당 서비스시간 | 15~120분 | 15분 |
| 1일 최대 방문 수 | 1~7곳 | 정수 1곳 |

빠른 비교안은 최소안 1대·기본안 3대·확대안 5대이고 다른 입력 조합도 위 범위에서
계산한다. 차량×운영일이 14보다 작으면 모든 시군 최소 1회 배정은 불가능하므로,
최소배정 제약을 풀고 P1→P2 순으로 일부 시군에 배정한 결과임을 화면에 경고한다.

## 3. 대상·후보·시군 계약

- 분석 모집단: 전북 243개 행정동 대표점
- 임계치 초과: 도로거리 3km 초과 71개
- 경로 대상: `road_distance_primary=Y` 69개
- 품질 유보: 대형 도로 연결구간 폴백 2개; 순위화하지 않고 사유를 출력
- P1: 기본 도로거리 5km 초과 26개
- P2: 기본 도로거리 3km 초과 5km 이하 43개
- 서비스구역: 14개 시군; 전주시 완산구·덕진구는 하나의 서비스구역으로 결합
- 후보 원천: 전북 공식 경로당 6,880건
- 좌표 감사: 6,856건 좌표화, 6,854건 원천 시군·SGIS 경계 일치, 실패 24건·불일치 2건 제외
- 경로 후보: 각 대상 행정동 안에서 대표점과 직선으로 가장 가까운 경로당 1곳, 총 69곳
- 후보 선정거리는 직선거리, 실제 순서 계산은 시군 내 방향성 OSM 도로거리

경로당 목록 등재는 차량 방문 승인이나 특정 시간 이용 가능성을 보증하지 않는다.
후보는 각 대상에 1:1로 붙인 **운영 프록시**이며 후보 위치를 최적화한 결과가 아니다.

## 4. 배정·경로 방법

1. 14개 시군에 최소 1개 경로일을 우선 배정한다.
2. 남은 경로일은 P1, P2, 전체 방문 대상 수를 순서대로 최대화하는 시군에 배정한다.
3. 각 시군의 후보가 최대 7개이므로 부분집합 동적계획법으로 선택방문·시간창·복귀제약 안의 시군별 경로를 정확 비교한다.
4. 전역 배정은 경로일 용량 안의 사전식 동적계획법으로 결정한다.

목표 순서는 `P1 방문 대상 수 → P2 방문 대상 수 → 전체 방문 대상 수 → 이동+대기시간 → 최대 운영시간`이다.
가중합 취약점수를 사용하지 않는다. 기준선은 **같은 시군별 경로일 배정**에서 현재 위치와
도로시간이 가장 가까운 방문 가능 후보를 반복 선택하는 최근접 탐욕법이다.

## 5. 출력 계약

| 경로 | 의미 |
|---|---|
| `status` | `operational_ready` 또는 `demonstration_not_operational` |
| `scope` | 243개 분석, 14개 시군, 71개 임계치, 69개 경로대상, 2개 품질유보 |
| `input_hashes` | 도로·유형·거점·접점·설정 파일 일치 검사 |
| `travel_model` | 일방통행, 연결구간, 상호도달 폴백, 실제 교통 여부 |
| `excluded_targets` | 품질로 순위화하지 않은 대상과 사유 |
| `depots_by_zone` | 시군별 출발·복귀 후보와 확정상태 |
| `engine_input.zones` | 시군별 대상·후보·방향성 행렬 |
| `results.zone_allocations` | 시군별 경로일 배정 |
| `results.baseline` | 같은 시군 용량의 최근접 탐욕 기준선 |
| `results.optimized` | 시군 배정+제약형 부분집합 DP 결과 |
| `input_controls` | 화면 입력의 최소·최대·증분 |
| `sensitivity_presets` | 최소·기본·확대안의 입력과 서버 기준 결과 |
| `measurement_contract` | 방문 대표점·주민 커버리지·후보 프록시의 해석 경계 |
| `routes[]` | 주기일·차량·시군·방문순서·도착·서비스·복귀 |
| `temporal_access` | 서비스주기, 경로일 용량, 미방문 스케줄 여부 |
| `unvisited_targets` | 미방문 대상과 사유 |
| `assumption_flags` | 운영 전 필수 확인 가정 |

UI는 `status`, `actual_traffic_time`, `interzone_repositioning_modeled`,
`confirmation_status`, `use_approval_status`, `time_window_source`, `excluded_targets`를 숨기면 안 된다.
P1·P2는 법정 금융소외 등급이 아니라 이번 시나리오의 운영 우선순위다.
`covered_target_count`는 엔진 호환 필드명이며 뜻은 **방문하는 행정동 대표점 대상 수**다.
주민별·격자별 출발점이 없어 주민 커버리지나 접근성 개선 인구를 산출하지 않는다.

## 6. 현재 기본 시나리오

- 차량 3대, 주기 내 5개 운영일, 총 15개 경로일
- 14개 시군 모두 최소 1개 경로일, 완주군 2개 경로일
- 최근접 기준선: 57개 방문, P1 22개·P2 35개, 1,007.062km
- 제약형 결과: 57개 방문, P1 26개·P2 31개, 1,055.555km
- 제약형은 품질 통과 P1 26개를 모두 포함하고 P2 12개는 미방문
- 기준선 대비 총 방문 수는 같고 P1 +4, 이동거리 +48.493km, 추정 이동시간 +72.740분
- 진안군 후보 1곳은 방향성 상호도달 노드 폴백을 사용했으며 연결구간은 45.744m

이는 “최적화가 거리를 줄였다”는 결과가 아니다. 한정된 용량에서 P1 방문 대상 수를 거리보다
먼저 두었기 때문에 이동량이 늘어난 명시적 정책 선택이다.

1일 최대 방문 수 1~7곳에서 전체 방문은 15·30·45·57·63·68·68곳으로 변한다.
30·40·50km/h와 30·45·60분 서비스시간의 9개 조합은 방문상한 4곳을 고정하면 모두 57곳이다.
따라서 현재 기본안에서 먼저 구속되는 가정은 속도보다 1일 최대 방문 수이며, 운영확정값으로
해석하지 않는다. 전체 민감도와 점포상태·후보거리 감사는 `reports/scenario_evidence.md`다.


## 8. 운영 전 확인할 값

- 참여기관이 확정한 14개 시군별 실제 출발·복귀지
- 차량 대수, 운영일, 운전자 근무, 시군 간 재배치·박차 소요시간
- 각 경로당의 장소 사용승인과 차량 진입 가능 여부
- 거점별 이용 가능 요일·시간과 휴무일
- 업무범위에 따른 실제 서비스시간
- 교통시간 또는 현장 주행시간 보정
- 2개 도로거리 품질 유보 대상의 대체 접근성 확인

이 값이 확인되기 전에는 `operational_ready=false`를 유지한다.
