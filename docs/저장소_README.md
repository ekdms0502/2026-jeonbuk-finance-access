# 전북 금융 사각지대 진단과 찾아가는 은행 최적 동선 설계

2026 제4회 전북 청년 AI·빅데이터 경진대회 · 현안 해결 구현 분야 제출작.
팀명 **금방**(금융 방방곡곡) · 대표자 정다은.

전북 **14개 시군·243개 행정동**의 금융 접근성을 진단하고, 제한된 차량·일정·거점
조건에서 찾아가는 금융 서비스의 시군별 순회 거점과 방문 순서를 제안한다.

## 팀원용 빠른 시작

저장소에는 바로 분석·시각화에 사용할 수 있는 `data/processed/` 가공 데이터가 포함되어 있다.
대용량 원본 데이터나 외부 서비스 연결 없이 아래 오프라인 검증을 실행할 수 있다.
검증 환경은 Python 3.11 이상과 브라우저 시나리오 테스트용 Node.js 20 이상을 사용한다.

```bash
git clone <저장소-URL>
cd jeonbuk-finance-access
python3 -m venv .venv
source .venv/bin/activate
python3 -m pip install -r requirements.txt
bash verify_offline.sh
open docs/demo-jeonbuk/index.html  # 전북 243개 행정동·운영 시나리오 비교
```

원본 파일의 출처·수집일·경로·정제 규칙은 `DATASETS.md`에 기록했다. 원본은 크기와
재배포 조건 때문에 GitHub에 올리지 않는다.

`verify_offline.sh`는 깨끗한 GitHub 체크아웃에서 원본·API 키 없이 실행되는 제출 검증이다.
원천 스냅샷을 보유한 갱신 담당자는 별도로 `bash verify_source_lineage.sh`를 실행해
`data/source_manifest.json`의 SHA-256, 새마을금고 수집 로그, 행정경계 포함관계를 확인한다.

## API 키 설정 (최초 1회)

키는 `.env`에만 넣는다. 이 파일은 `.gitignore`에 등록되어 git에 올라가지 않는다.

```bash
open -e .env    # 또는 원하는 편집기로
```

`ECOS_API_KEY=PASTE_YOUR_KEY_HERE` 의 오른쪽을 발급받은 키로 바꾸고 저장한다.
따옴표·공백 없이 값만 붙여넣으면 된다.

```bash
./verify.sh     # 키 설정 + 데이터 + ECOS 연결 확인
```

## ECOS 사용 메모

- 통계표 `141Y003` 예금은행 지역별 대출금(말잔), 월간
- 항목 순서가 **(계정항목, 지역)** 이어야 한다 — `200000/Q00`. 뒤집으면 `INFO-200`
- `Q00` = 전북
- ECOS에는 **지역별 점포수 통계가 없다** (전국 단위 `901Y123` 1건뿐). 그래서 점포
  시계열은 쓰지 않고, 점포 접점은 은행연합회·신협·새마을금고 공개 조회로 직접 수집했다.

**운영 확정 전 한계(의도적으로 남긴 상태):** 후보거점 사용승인과 실제 시간창은
운영 주체가 확정해야 하는 값이라 시연에서는 명시적 가정값으로만 쓴다. 이 상태는
대시보드의 `operational_ready=false`와 운영 상태 패널에 그대로 표시된다.

거리 결과는 행정동 내 한 대표점에서 계산한 **접근성 프록시**다. 주민별 노출거리나
“3km 밖 고령인구”로 해석하면 안 된다. 상세 한계는 `reports/quality_report.md`를 따른다.

취약유형은 전북 읍·면 중 기본 도로거리 품질을 통과한 비교집단에만 적용한 탐색 결과다.
도시 동과 도로거리 폴백에는 모델 라벨을 강제로 부여하지 않으며, 정책순위로 사용하지 않는다.
`k=2..5` 중 재표집·최소크기·전처리 민감도 게이트를 모두 통과한 후보에서 실루엣이 가장
높은 `k=2`를 선택했다(실루엣 0.686, 재표집 ARI 중앙 1.000, `log1p` 대안 ARI 0.779).
검증 결과는 `reports/typology_evaluation.md`를 따른다. 입력의 `road_km`는 OSM 도로거리,
`cnt_3km`는 대표점 기준 직선거리 접점 수로 서로 다른 거리 정의를 명시한다.

기본 순회 시나리오는 전북 243개 대표점을 모집단으로 하고, 도로거리 3km 초과 71개 중
기본 도로거리 품질을 통과한 69개를 경로대상으로 사용한다. 차량 3대·5일·시군별 최소
1개 경로일 조건에서 기준선과 제약형 모두 57개를 방문하지만, 제약형은 P1을 22개에서 26개로
늘려 품질 통과 P1을 모두 포함한다. 이동시간은 OSM 도로거리÷40km/h 가정이며 차고지·장소 사용승인·
시간창·시군 간 차량 재배치가 확인되지 않았으므로 `operational_ready=false`다. 계약은
`docs/SCENARIO_CONTRACT.md`를 따른다.

대시보드 입력은 차량 수·운영일·1일 최대 방문 수를 정수로, 장소당 서비스시간을 15분
단위로, 시작·종료 시각을 30분 단위로 받는다. 최소안 1대는 20/69곳, 기본안 3대는
57/69곳, 확대안 5대는 69/69곳을 방문한다. 이는 같은 거점·도로행렬을 둔 정책
민감도 비교이며 실제 운영 확정값이 아니다.

기본안의 `57/69`는 **방문하는 행정동 대표점 대상 수**이며 주민 커버리지나 접근성 개선
인구가 아니다. 1일 최대 방문 수를 1~7곳으로 바꾸면 방문 수가
15→30→45→57→63→68→68로 변한다. 30·40·50km/h와 30·45·60분 서비스시간의 9개
조합에서는 최대 방문 수 4곳이 먼저 구속되어 모두 57곳이었다. 점포 상태와 후보-대표점
거리까지 포함한 감사 결과는 `reports/scenario_evidence.md`와
`data/processed/scenario_evidence.json`을 따른다.

지도는 SGIS 2026 행정동 경계, OSM 주요도로, 저장된 방향성 거리행렬과 일치하는 최단경로
형상을 사용한다. 점 색은 우선순위·거리·취약유형, 점 크기는 65세 이상 인구·고령비율·
도로거리 중 하나를 독립적으로 표현한다. 전체 OSM 활성 노드 약 184만 개 대신 현재 경로를
구성하는 노드를 구간당 최대 64개 표본으로 표시한다. 계산 설명은
`docs/demo-jeonbuk/methodology.html`에서 확인한다.
